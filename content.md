## 1. CONTENT STRATEGY

### Primary Positioning

Frontend Developer / React Developer / Product Builder

### Communication Goal

> I build polished, functional digital products with a strong focus on frontend engineering, user experience, and product thinking.

### Tone

- Confident
- Clear
- Technical
- Human
- Concise
- Professional
- Modern

### Writing Voice

Write like a builder talking to other builders. Not like a marketer. Not like a textbook. Not like an AI.

### What to Avoid

- Generic motivational statements
- Buzzword-heavy copy
- Fake seniority or exaggerated claims
- Corporate jargon
- Long paragraphs
- AI-sounding language ("passionate about crafting innovative solutions")
- Repeating the same description across sections

|---|---|

| Accessibility | Semantic HTML, keyboard navigation, screen reader support, WCAG-conscious contrast. |
| UI State | Managing loading, error, empty, and success states. Every state is a design decision. |

## 24. CONTENT RULES

### Do

- Use short sentences
- Use active voice
- Lead with outcomes
- Explain technical work clearly
- Use concrete terminology
- Show engineering thinking
- Keep copy scannable
- Write like a builder, not a marketer

### Don't

- Use fake metrics
- Use fake client names
- Claim seniority without evidence
- Overuse "passionate"
- Overuse "innovative"
- Use generic AI-generated phrases
- Write huge paragraphs
- Repeat the same description everywhere
- Use buzzwords without substance
- Exaggerate achievements
